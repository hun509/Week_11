# SyncBeat : 실시간 DJ 음악 동시 감상 & 타임스탬프 채팅 서비스

## 1. 서비스 소개 · 대상 사용자와 핵심 기능

- **대상 사용자**: 학과 공지·시험 기간·게임 대기 시간 등에 같은 배경음악(BGM)을 실시간으로 함께 들으며 이야기하고 싶은 대학생 및 게이머
- **구현 시나리오 (접속 집중 상황)**: 인기 DJ의 저녁 피크 타임(예: 22:00) 방송 오픈 직후 또는 게임 이벤트 대기 시간에 다수의 사용자가 동시에 리스닝 룸에 입장하고 실시간 타임스탬프 댓글을 집중 전송하는 상황
- **핵심 사용자 기능 (3개 이상)**
  1. **리스닝 룸 생성 및 입장 (`POST /api/rooms`, `GET /api/rooms`)**: 방 제목(1~40자), 호스트 닉네임(1~20자), 최대 정원(2~200명)을 입력해 방을 생성하고 목록에서 입장
  2. **DJ 선곡 및 `<audio>` 재생 시점 실시간 동기화 (`POST /api/rooms/<id>/playback`)**: 내장 샘플 음원 또는 **AWS S3**에 저장된 음원 객체 URL을 선택하고 재생 위치(0~3,600초) 및 재생/일시정지 상태를 방 전체 참여자의 HTML5 `<audio>` 태그에 동기화
  3. **실시간 타임스탬프 감상 댓글 (`POST /api/rooms/<id>/comments`)**: 현재 곡의 서버 기준 재생 시점(예: `[00:14]`)과 함께 감상평·채팅(1~200자)을 실시간 등록 및 공유

## 2. AWS 구성도 · 요청 경로와 서비스 선택 이유

### 배포 구조도 및 사용자 접속 경로

```text
[사용자 브라우저]
   │
   ├─ (1) 웹 화면 · API · 동기화 요청 : http://<EC2_퍼블릭_IP>:8080
   ▼
[AWS EC2 (Ubuntu 24.04 LTS · Docker Compose)]
   │  (호스트 포트 8080 → 컨테이너 포트 80)
   ├── [nginx 컨테이너 (syncbeat_web01 :80)]
   │      ├─ 정적 화면 제공 (index.html, style.css, app.js, 기본 샘플 음원)
   │      └─ /api/* 요청 리버스 프록시 전달 (http://api:5000)
   └── [api 컨테이너 (syncbeat_api01 :5000, Flask)]
          └─ 방 생성/조회, 서버 시간 기반 재생 시점 계산, 타임스탬프 댓글 저장
   
   ├─ (2) 음원 파일 스트리밍 로드 (선택/권장 연동)
   ▼
[AWS S3 (정적 음원 객체 저장소)]
   └─ https://<버킷명>.s3.<리전>.amazonaws.com/sample_track_1.wav (HTML5 <audio> 직접 재생)
```

### 사용한 AWS 서비스 및 선택 이유

| 구분 | 적용 여부 | 선택 이유 및 운영·비용 근거 |
| :--- | :---: | :--- |
| **AWS EC2** | **적용 (필수)** | `compose.yaml`에 정의된 `nginx`와 `api(Flask)` 두 컨테이너를 동일 Docker 네트워크(`syncbeat_net01`) 위에서 빠르게 배포·검증하기 위해 `t3.micro` 인스턴스를 선택함 |
| **AWS S3** | **적용 (음원 객체 저장)** | 오디오 파일(`.wav`/`.mp3`)을 EC2 컨테이너 내부에만 두면 트래픽 집중 시 웹 서버 대역폭 부담이 커지므로, 정적 미디어 객체를 S3에 분리 저장해 `<audio>` 태그가 URL로 직접 스트리밍하도록 구성함 |
| **ELB (ALB) · Auto Scaling** | **미적용 (검토 완료)** | **검토 근거**: 실제 상용 피크 타임(수백 명 동시 접속)에서는 ALB로 요청을 분산하고 EC2 Auto Scaling(최소 1대~최대 3대)과 공유 캐시(Redis)를 붙여야 하나, 이번 학기 과제는 소규모 시연 검증 목적이며 **ALB 시간당 고정 유지 비용 및 다중 EC2 과금을 방지(비용 관리)**하기 위해 단일 EC2(`t3.micro`)로 구성하고 시연 완료 후 즉시 중지·정리하는 방식을 채택함 |

## 3. 실행 · 배포 방법 (로컬 및 AWS EC2)

### ① 로컬 점검 (Windows Docker Desktop / PowerShell)

```powershell
# 1. Compose 설정 문법 확인
docker compose config

# 2. 컨테이너 이미지 빌드 및 백그라운드 실행
docker compose up -d --build

# 3. 실행 상태 및 health 응답 확인
docker compose ps
curl.exe -i http://localhost:8080/api/health
```

- 로컬 접속 주소: `http://localhost:8080`

### ② AWS EC2 배포 명령 (Ubuntu 24.04 LTS 터미널)

- **사전 준비**: EC2 보안 그룹(Security Group) 인바운드 규칙에 **사용자 지정 TCP `8080` 포트** 허용 추가

```bash
# 1. GitHub 저장소 복제 및 폴더 이동
cd ~
git clone https://github.com/hun509/<저장소이름>.git
cd <저장소이름>

# 2. Docker Compose 빌드 및 실행
sudo docker compose up -d --build

# 3. 컨테이너 상태 및 health 확인
sudo docker compose ps
curl -i http://localhost:8080/api/health
```

- **AWS 배포 접속 주소**: `http://<EC2_퍼블릭_IP>:8080` (제출 시 본인 EC2 퍼블릭 IP로 기입)

| **기능 3: 타임스탬프 감상 댓글** | **실패/경계 (Boundary)** | 댓글 내용 공란(`""`) 입력 후 전송 클릭 | HTTP 400 및 빈 댓글 차단 메시지 출력 | `[실패/경계 확인] 댓글 내용을 입력하세요.` 출력 확인 |
