# SyncBeat : 실시간 DJ 음악 동시 감상 & 타임스탬프 채팅 서비스

## 1. 서비스 소개 · 대상 사용자와 핵심 기능

- **대상 사용자**: 학과 공지·시험 기간·게임 대기 시간 등에 같은 배경음악(BGM)을 실시간으로 함께 들으며 이야기하고 싶은 대학생 및 게이머
- **구현 시나리오 (접속 집중 상황)**: 인기 DJ(호스트)가 방송방을 열거나 특정 시간(예: 22:00)에 다수의 게스트가 PC·모바일로 동시 접속해 실시간 재생 동기화와 타임스탬프 댓글을 집중 전송하는 상황
- **핵심 사용자 기능 (3개 이상)**
  1. **역할 선택 및 리스닝 룸 생성/입장 (`POST /api/rooms`, `POST /api/rooms/<id>/join`)**:
     - **호스트(DJ)**: 방 제목(1~40자), 호스트 닉네임(1~20자), 최대 정원(2~200명)을 입력해 새 방 생성
     - **게스트(청취자)**: 게스트 닉네임을 입력하고 참여 가능한 방 목록을 선택해 입장 (세션 하트비트 기반 실시간 접속 인원 정확 집계)
  2. **호스트 전용 AWS S3 음원 목록 선택 및 `<audio>` 자동 동기화 (`GET /api/s3/tracks`, `POST /api/rooms/<id>/playback`)**:
     - 방을 만든 호스트만 S3 버킷 내 음원 목록을 불러와 선곡하고, 재생/일시정지/구간 이동 시 게스트 브라우저의 `<audio>` 플레이어가 자동으로 동기화됨 (게스트 제어 차단 `403`)
  3. **실시간 타임스탬프 감상 댓글 (`POST /api/rooms/<id>/comments`)**:
     - 기능 1에서 설정한 닉네임으로 자동 작성되며, **실제 시각(KST)**과 **곡 재생 시점(MM:SS)**을 함께 기록하고 두 기준(실제 시간순 / 곡 재생 시간순)으로 정렬 가능

## 2. AWS 구성도 · 요청 경로와 서비스 선택 이유

```text
[사용자 브라우저 (호스트 PC / 게스트 모바일)]
   │
   ├─ (1) 웹 화면 · API · 2초 주기 동기화 폴링 : http://<EC2_퍼블릭_IP>:8080
   ▼
[AWS EC2 (Ubuntu 24.04 LTS · Docker Compose)]
   │  (호스트 포트 8080 → 컨테이너 포트 80)
   ├── [nginx 컨테이너 (syncbeat_web01 :80)]
   │      ├─ 정적 화면 제공 (index.html, style.css, app.js, 기본 샘플 음원)
   │      └─ /api/* 요청 리버스 프록시 전달 (http://api:5000)
   └── [api 컨테이너 (syncbeat_api01 :5000, Flask + boto3)]
          ├─ 방/세션 하트비트 관리, 호스트 권한 검증, 실시간 재생 시점 계산
          └─ AWS IAM 역할(week8-role)을 통해 S3 버킷 음원 목록 조회
   │
   ├─ (2) 음원 파일 목록 조회(boto3) 및 <audio> 스트리밍 로드
   ▼
[AWS S3 (정적 음원 객체 저장소)]
   └─ 버킷 내 .mp3/.wav 목록 자동 표시 및 객체 URL 직접 스트리밍
```

| 구분 | 적용 여부 | 선택 이유 및 운영·비용 근거 |
| :--- | :---: | :--- |
| **AWS EC2** | **적용 (필수)** | `compose.yaml`에 정의된 `nginx`와 `api(Flask)` 두 컨테이너를 Docker 네트워크(`syncbeat_net01`) 위에서 빠르게 배포·검증하기 위해 `t3.micro` 인스턴스를 선택함 |
| **AWS S3** | **적용 (음원 저장·목록 연동)** | 오디오 파일을 EC2 내부에만 두지 않고 S3 버킷에 분리 저장한 뒤, `boto3`로 버킷 파일 목록을 자동 조회하고 `<audio>` 태그가 S3 URL로 직접 스트리밍하도록 구성함 |
| **ELB (ALB) · Auto Scaling** | **미적용 (검토 완료)** | 대규모 동시 접속 시에는 ALB로 트래픽을 분산하고 EC2 Auto Scaling(1~3대) + Redis 공유 세션이 필요하지만, 소규모 과제 시연 목적상 **ALB 고정 시간 과금과 다중 인스턴스 비용을 절감**하기 위해 단일 EC2로 구성하고 검사 후 중지·정리함 |

## 3. 실행 · 배포 방법 (AWS EC2)

- **사전 준비**:
  1. EC2 보안 그룹 인바운드 규칙에 **TCP `8080` (`0.0.0.0/0`)** 허용
  2. EC2 IAM 역할(`week8-role`)에 **`AmazonS3ReadOnlyAccess`** 권한 추가 (S3 버킷 목록 자동 조회용)

```bash
cd ~
git clone https://github.com/hun509/<저장소이름>.git
cd <저장소이름>

# (선택) S3 버킷 이름을 환경변수로 지정하거나 웹 화면에서 직접 입력 가능
S3_BUCKET=<본인_S3_버킷이름> AWS_REGION=ap-southeast-2 sudo -E docker compose up -d --build

sudo docker compose ps
curl -i http://localhost:8080/api/health
```

- **AWS 배포 접속 주소**: `http://<EC2_퍼블릭_IP>:8080`
